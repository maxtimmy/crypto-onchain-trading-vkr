# Каталог данных первого эксперимента

Обновлено 20 октября 2026 года; первичная проверка источников выполнена 19 октября. Отладочный инструмент — **BTCUSDT, спот без плеча**. Он выбран для проверки пайплайна, без отбора по будущей доходности; результат по одной паре нельзя переносить на весь рынок.

## Артефакты и воспроизведение

Проверка выполняется собственными публичными GET-запросами без ключей. В [скрипте](../scripts/probe_sources.py) зафиксированы диапазоны запросов и проверки; Python 3.9+, дополнительных библиотек нет:

```bash
python3 scripts/probe_sources.py --as-of 2026-10-19
python3 -m unittest discover -s tests -v
```

Каждый запуск создаёт новый каталог `data/probes/<UTC-время>/`: `raw/` содержит исходные JSON-ответы, `manifest.json` — URL, параметры, время отправки/получения, HTTP-код, диагностические заголовки и SHA-256 каждого ответа; `summary.json` — результаты проверок. Старые запуски не перезаписываются. `--as-of` задаёт только конец свежего проверочного окна, а не историческую версию данных. Рядом сохраняется копия скрипта запуска.

После прерванной проверки можно передать `--reuse-run data/probes/<предыдущий-запуск>`: совпадающие успешные ответы используются повторно только после сверки размера и SHA-256. В манифесте сохраняются исходное время получения и путь предыдущего запуска. Это повторная проверка снимка, а не новое получение данных.

Исходные ответы остаются локально и исключены из Git. В репозитории хранится небольшая [сводка принятой проверки](../experiments/0001_source_probe_summary.json). Общего внешнего хранилища пока нет; удалённая копия репозитория без локальных ответов не содержит исходных данных. Повторный запрос может вернуть пересмотренную историю.

## Binance: свечи и объёмы

| Поле | Значение |
|---|---|
| Источник | [Spot Market Data Only](https://github.com/binance/binance-spot-api-docs/blob/master/faqs/market_data_only.md), `https://data-api.binance.vision` |
| Получение | `GET /api/v3/klines`, `symbol=BTCUSDT`, `timeZone=0`, `startTime`, `endTime`, `interval`, `limit=1000`; без аккаунта |
| Детализация | Для фичей исходные `1h`, из них UTC-свечи `4h`/`1d`; отдельные `1d` для проверки; `1m` для будущих цен исполнения |
| Схема строки | `open_time`, `open`, `high`, `low`, `close`, `volume`, `close_time`, `quote_asset_volume`, `trade_count`, `taker_buy_base_volume`, `taker_buy_quote_volume`, игнорируемое поле |
| Единицы | OHLC — USDT/BTC, основной объём — BTC, котируемый — USDT; REST-время по умолчанию в миллисекундах UTC |
| Ключ | `(symbol, interval, open_time)` |
| Пагинация | Следующий `startTime = last_open_time + interval`; проверять продвижение и полуоткрытые границы `[start, end)` |
| Лимиты | Вес `/klines` — 2, максимум 1000 свечей; действующие общие лимиты — в сохранённом `/exchangeInfo`, расход — в `X-MBX-USED-WEIGHT-*` |
| Ошибки | При 418/429 проверка останавливается с сохранением ответа; перед новым запуском соблюдать `Retry-After`. Сетевой отказ не трактовать как отсутствие истории |
| Текущие правила | `/exchangeInfo?symbol=BTCUSDT`: статус, base/quote, фильтры и разрешения; это снимок текущих, а не исторических ограничений |

[Описание свечей](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market), [общие правила и лимиты](https://developers.binance.com/en/docs/products/spot/rest-api), [фильтры заявок](https://developers.binance.com/en/docs/products/spot/filters).

REST хранит время открытия/окончания интервала, но не время первой публикации свечи. В WebSocket есть признак закрытия `k.x` и время события `E`; историческая REST-выгрузка не восстанавливает их. Асинхронность и задержки описаны, гарантированного максимального лага нет. Для исторической модели используем только завершённые свечи; задержка исполнения в паспорте эксперимента — **сценарное допущение**, не измеренная задержка биржи. Исторические исправления исключить нельзя: [архив Binance](https://github.com/binance/binance-public-data) предусматривает обновление опубликованных файлов. Одна выгрузка не проверяет отсутствие пересмотров REST.

**Условия.** [Spot API Terms](https://github.com/binance/binance-spot-api-docs/blob/master/PROD-TERMS-OF-USE.md) отсылают к условиям Binance. [Vision Dataset Terms v1.0](https://github.com/binance/binance-public-data/blob/master/TERMS_AND_CONDITIONS.md), обновлённые 26 августа 2026 года, предусматривают бесплатные академические исследования и некоммерческие бэктесты, CC BY-NC-SA 4.0, атрибуцию и ограничения коммерческого использования. Их область — `data.binance.vision and associated endpoints`; применимость ко всем REST-ответам прямо не уточнена. MIT-лицензия программного кода не считается лицензией данных. В этой проверке сырые данные не публикуются; перед распространением производных данных и использованием сервиса за пределами учебного исследования условия нужно проверить для конкретного использования.

| Лицензия | [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/): атрибуция Coin Metrics, ссылка на источник/лицензию, обозначение преобразований; коммерческое использование не разрешено автоматически |

Показатели относятся к сети Bitcoin и используются только для BTC. Их нельзя без обоснования переносить на другие активы.

| Показатель | Смысл и единицы | Решение |
|---|---|---|
| `TxCnt` | [Число транзакций](https://docs.coinmetrics.io/network-data/network-data-overview/transactions/transactions) за день; для BTC без coinbase | Кандидат на фичу после проверки исторических версий |
| `AdrActCnt` | [Число уникальных активных адресов](https://docs.coinmetrics.io/network-data/network-data-overview/addresses/active-addresses) отправителей/получателей за день; это не число людей | Кандидат на фичу после проверки исторических версий |
| `AssetEODCompletionTime` | [Время завершения дневных расчётов](https://gitbook-docs.coinmetrics.io/network-data/network-data-overview/availability/asseteodcompletiontime), Unix seconds | Диагностика доступности, не предиктор и не сертификат исторической версии |
| `TxTfrValNtv` | [Объём переводов](https://docs.coinmetrics.io/network-data/network-data-overview/transactions/transfer-value), BTC | В текущей проверке бесплатный запрос вернул HTTP 403; исключён |
| `TxTfrValAdjNtv` | Скорректированный эвристиками объём переводов, BTC | В текущей проверке бесплатный запрос вернул HTTP 403; исключён |

Метрики проверяются раздельно: отказ одной не должен скрывать доступные остальные. Наличие метрики в общей документации не означает доступность в Community.

## Доступность во времени и допуск в бэктест

У CamelCase-метрик поле `time` обозначает **начало агрегируемого интервала** ([FAQ](https://docs.coinmetrics.io/service-and-support/faqs.md)). Строка за 1 января содержит итоги дня и неизвестна в его начале. Расчёты начинаются после 00:00 следующих суток и заканчиваются в переменное время.

`AssetEODCompletionTime` сообщает о завершении расчётов дневных метрик актива. Документация не обещает неизменяемую связь этого поля с первой публикацией каждого конкретного значения. Оно не восстанавливает прошлые версии `TxCnt`/`AdrActCnt`. Параметр `status=all|flash|reviewed|revised` применяется к human-reviewable метрикам, не выбирает срез истории на прошлую дату и не является универсальным статусом стабильности. Для выбранных счётчиков нельзя требовать `reviewed` как условие корректности.

В документированном методе `/timeseries/asset-metrics` нет выбора `as_of`/`vintage`. Сам факт наличия исторических значений и времени расчёта **не подтверждает point-in-time** — соответствие версии тому, что было известно в момент торгового решения. Постоянный лаг в один или несколько дней проблему пересмотров не устраняет.

**Допуск ончейн-фичей в основной исторический бэктест пока не подтверждён.** Нужны проверяемые снимки прошлых версий с временем доступности, документированная гарантия поставщика либо самостоятельно восстановленные значения из доступных в тот момент записей сети. Собственные снимки, собираемые сейчас, помогут будущей бумажной торговле, но не исправят историю 2022–2025 годов. Текущие выгрузки допустимы для исследования структуры и проверки сборки; рыночный технический запуск не считается выполнением расширенного эксперимента.

После допуска объединять источники по `available_at <= feature_cutoff`, сохранять `event_time`, `retrieved_at`, идентификатор версии и возраст последнего доступного значения. Пропуски цен не интерполировать. Для допускаемых редких ончейн-обновлений переносить только уже опубликованное значение, помечать возраст; при возрасте более 72 часов пропускать сигнал. Эта граница — стартовое исследовательское допущение, а не свойство API.

**Локальные дефекты рынка подтверждены повторно.** Нет свечи `2023-03-24 13:00 UTC`. Свечи `2021-12-24 04:00` и `2023-03-24 12:00` имеют длительность соответственно 3 594 363 и 2 381 647 мс вместо 3 600 000 мс. Причина в этой проверке не установлена; автоматически объявлять их ошибкой цены или заполнять недостающий час нельзя. Сборка должна пометить эти интервалы и исключать решения, в чьи окна попадает отсутствующая/неполная свеча. Полные дневные ответы не отменяют дефектов часовой базы.

Coin Metrics после соединения страниц нужно сортировать по времени и повторно проверять ключи; это особенность полученного порядка, а не доказательство неверности самих значений. В будущих запросах можно явно задать документированный `paging_from=start`.

**Календарного покрытия достаточно**, чтобы выделить обучение 2022–2023, валидацию 2024 и финальный тест 2025; это оценка объёма истории, а не доказательство предсказательной силы. На этапе 0001 готового датасета ещё не было. Полная рыночная сборка выполнена следующим этапом, описанным ниже; подтверждение исторических версий ончейн-фичей остаётся отдельным ограничением.

## Границы первичной проверки 0001

Скрипт пробных запросов проверяет полную часовую и дневную сетку рынка с 1 декабря 2021 года до 1 января 2026 года, дневные ончейн-ряды того же периода, старые/свежие контрольные окна и два двухчасовых отрезка `1m`. Это проверка текущего снимка, без обучения, вычисления торговой доходности или выбора по финальному тесту. Полная минутная история в первичную проверку не входила.

Проверки включают ожидаемое число временных точек с обоими краями диапазона, повторы ключей, порядок, пропуски метрик, конечность/знак чисел, OHLC-ограничения, длительность свечи, неоконченные интервалы. Пройденные проверки не доказывают отсутствие экономических выбросов, всех ошибок поставщика или исторических пересмотров. Фактические результаты принятого запуска записаны в сводке и паспорте эксперимента.

## Полная рыночная версия 0002

[Сборка 0002](../experiments/0002_market_dataset.md) охватывает весь `[2021-12-01, 2026-01-01)` для `1m` и `1h`. Получены 2185 страниц, 2 148 400 из 2 148 480 минутных и 35 807 из 35 808 часовых точек. В минутном ряду отсутствуют 80 минут `[2023-03-24 12:40, 14:00)` UTC. По две свечи каждого масштаба имеют нестандартную длительность; повторы ключей и лишние точки не обнаружены.

Из этой базы построены 33 795 строк и 18 фичей для `1h / 4h`; 1269 решений исключены с сохранением причин. Пропуски не интерполируются. Версии исходных ответов, состояние загрузки и данные SQLite хранятся локально вне Git; содержательные хеши и количества — в [сводке](../experiments/0002_market_dataset_summary.json). Команды и контракт хранения — в [инструкции](data_pipeline.md).

Проверка целостности сопоставляет SQLite с исходными ответами, а не только проверяет хеши файлов. Повторная сборка сохраняет тот же отпечаток таблицы. Ончейн в рыночную версию не включён: [дополнительная проверка архивов и блоков](onchain_history.md) не подтвердила исторический `available_at`.
