# Первое обучение CatBoost

Эксперимент `0003_btcusdt_1h_4h` сравнивает два заранее заданных CatBoost и два постоянных прогноза на готовой рыночной таблице BTCUSDT. Это проверка качества прогноза четырёхчасовой доходности до расходов. Торговые показатели, выбор стратегии и ончейн-фичи в этот запуск не входят.

## Окружение и запуск

Команды выполняются из корня проекта. Нужны `uv` и локальный снимок `data/datasets/btcusdt_1h_4h_v1/market.sqlite3` с сохранёнными исходными ответами. Его подготовка описана в [инструкции пайплайна](data_pipeline.md).

```bash
uv sync --locked
uv run --locked python scripts/train_model.py train --config configs/catboost_1h_4h.json
```

`uv` создаёт отдельное окружение `.venv`: Python 3.12.3 выбран в `.python-version`, CatBoost 1.2.10 и NumPy 1.26.4 зафиксированы в `pyproject.toml`, остальные зависимости — в `uv.lock`. Параметры запуска находятся в [catboost_1h_4h.json](../configs/catboost_1h_4h.json). Перед обучением проверяются целостность базы, соответствие закреплённым `snapshot_id` и `expected_dataset_sha256`, точный состав фичей и временные границы.

**Повторный `train` запускает два новых обучения.** Это не проверка ранее сохранённого запуска. Общий журнал `budget_ledger` — `artifacts/training/attempts.jsonl`; он учитывает все начатые попытки, включая неудачные и прерванные. Параллельные запуски с тем же журналом блокируются.

Общего предела в 20 обучений нет: это число появилось как размер первоначальной сетки, а не обоснованный лимит проекта. В старых отчётах оно сохранено как историческая настройка; в текущем коде ограничение снято. Для каждого нового этапа заранее фиксируются конкретные конфигурации и число запусков. Попытки разных вариантов с одинаковой глубиной различаются по идентификатору, прежние записи журнала поддерживаются. Проверка окружения или данных до начала обучения не считается обучением; причина неудачи сохраняется в отчёте запуска.

Для проверки последнего завершённого запуска без нового обучения:

```bash
uv run --locked python scripts/train_model.py verify --config configs/catboost_1h_4h.json
```

Конкретный сохранённый запуск выбирается через `--run-dir artifacts/training/0003_btcusdt_1h_4h/run-...` с его настоящим именем. `verify` сверяет контрольные суммы, версии окружения, идентичность строк и метрики; загружает обе модели и повторяет их прогнозы. Вызовов `fit` нет, бюджет не расходуется. Используется то же окружение, включая версии Python, пакетов и архитектуру, что записано в отчёте.

## Данные и параметры

Обучающая часть — `[2022-01-01, 2024-01-01)`, валидация — `[2024-01-01, 2025-01-01)`, всё в UTC. Части определяются по времени исполнения; конец четырёхчасового ответа тоже должен находиться внутри своей части. Модель получает только 18 фичей:

- Доходность, диапазон и объём BTC последней закрытой часовой свечи.
- Для каждого окна 24, 168 и 720 часов: доходность, реализованную волатильность, суммы объёмов BTC и USDT, диапазон цен.

Целевая доходность и служебные времена не входят в признаки. Фичи рассчитаны по закрытым часам; сценарная доступность — через 60 секунд после границы часа, исполнение — через 120 секунд. Ответ `y = open_1m(execution_time + 4 часа) / open_1m(execution_time) − 1` использует точные минутные открытия. Пропуски и неполные окна уже исключены при сборке, без интерполяции.

Два варианта отличаются только глубиной: `depth=4` и `depth=6`. Общие параметры: 300 итераций, `learning_rate=0.05`, `l2_leaf_reg=3`, `random_seed=42`, `loss_function=RMSE`, `task_type=CPU`, `thread_count=1`, `has_time=true`, `use_best_model=false`. Ранняя остановка отключена; валидация не передаётся в `fit`. Проверяется наличие ровно 300 деревьев. Новые глубины, подбор параметров и расширение сетки этим запуском не предусмотрены.

Базовые методы — `zero` и `train_mean`: соответственно ноль и средняя целевая доходность только обучающей части. Одно обучающее среднее применяется также к валидации. Все четыре метода оцениваются на одних и тех же строках каждой части.

Сохраняются RMSE, MAE и число строк: в целом и по календарным кварталам, определённым по `execution_time` в UTC. Метрики обучения нужны для диагностики; проверка качества вне обучения относится к 2024 году. Ежечасные четырёхчасовые ответы перекрываются, поэтому ошибки зависимы. Интервалы значимости и тесты с предположением независимых строк не рассчитываются.

## Локальные артефакты

Каждый запуск создаёт новый каталог `artifacts/training/0003_btcusdt_1h_4h/run-.../`, не перезаписывая предыдущий. Данные и артефакты исключены из Git; в репозитории остаются код, конфигурация, lock-файлы и краткая запись эксперимента.

| Файл | Содержание |
|---|---|
| `report.json` | Статус, параметры, версии, число строк, хеши снимка и выбранных строк, метрики, сведения о попытках и ошибках |
| `manifest.json` | Контрольная сумма отчёта и файлов; создаётся только для успешного полного запуска |
| `config.json` | Конфигурация запуска |
| `depth4.cbm`, `depth6.cbm` | Сохранённые модели CatBoost |
| `predictions.csv.gz` | Прогнозы всех четырёх методов для обучения и валидации: времена решения/исполнения/конца ответа, часть, `y_true`, `y_pred`, метод |
| `metrics.json` | Метрики по методам, частям и кварталам |
| `source/` | Копии исходников, конфигураций, описания окружения и lock-файлов с зафиксированными контрольными суммами |

После ошибки каталог и `report.json` сохраняются; полного набора артефактов у такого запуска может не быть. После успешного обучения загрузка CBM должна воспроизводить сохранённые прогнозы с абсолютным допуском `1e-12`; `verify` повторно проверяет это условие и пересчитывает метрики без обучения.

CatBoost округляет часть дробных параметров в метаданных CBM. Только для их сопоставления используется `rel_tol=1e-9`, `abs_tol=1e-12`; типы, ключи и структура остаются строгими. Контрольные суммы файлов проверяются точно. Если проверяющий код исправлен после обучения, исходный снимок запуска сохраняется, а хеш использованной версии проверки фиксируется отдельно в сводке эксперимента.

## Границы эксперимента

Финальная часть 2025 года не передаётся в модели, прогнозы или метрики. Техническая проверка целостности может читать весь снимок, включая финальные строки; это не оценка качества на финальном периоде.

Ончейн не включён из-за неподтверждённого исторического времени доступности версий; обоснование находится в [разборе источников](onchain_history.md). Этот эксперимент не является бэктестом: комиссии, проскальзывание, позиции и доходность стратегии здесь не рассчитываются. Его результаты не доказывают прибыльность торговли.
