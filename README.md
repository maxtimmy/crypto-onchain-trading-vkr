# Алгоритмическая торговля криптовалютой

Проект ВКР: сервис, который обновляет данные, рассчитывает прогнозы и управляет позициями на виртуальном счёте. Выбор модели, признаков и торговых правил проверяется в экспериментах.

## Сейчас

Готовы загрузчик с продолжением, [рыночная таблица BTCUSDT](experiments/0002_market_dataset.md) из 33 795 строк и 18 фичей и [первые два CatBoost](experiments/0003_catboost.md) для часовых решений с горизонтом 4 часа. Модели обучены на 2022–2023 годах и проверены на 2024: оба варианта уступили постоянным прогнозам по RMSE и MAE. Бюджет — 2 из 20 сравнительных обучений. Модели, прогнозы, исходные ответы и SQLite хранятся локально вне Git; небольшие сводки — в `experiments/`. Финальный 2025 год не оценивался. Бэктест и сервис ещё не реализованы.

[Диагностика 0004](experiments/0004_catboost_diagnostics.md) без новых обучений показала отрицательный сдвиг прогнозов и проигрыш по MSE во всех трёх группах волатильности. Ухудшение не ограничено крупными движениями. Сохранены помесячные срезы, разложение ошибок, изменения распределений фичей и воспроизводимые графики; причины пока сформулированы как проверяемые гипотезы.

Исторические версии ончейн-метрик пока не подтверждены для основного бэктеста. Проверены [архивы и реконструкция из блоков](docs/onchain_history.md); ограничения описаны явно. Рыночная таблица не заменяет запланированное сравнение с дополнительными фичами.

## Ход работы

1. Определить цель прогноза, правила выбора инструментов и начальные эксперименты; проверить доступ к источникам.
2. Написать загрузчики истории и обновления через API. Подготовить рыночные и первые ончейн-фичи.
3. Обучить бустинг и проверить торговые решения в бэктесте с расходами и ограничениями исполнения.
4. Сравнить временные настройки, признаки и модели на нескольких инструментах. Выбрать стратегию и провести закрытый финальный тест.
5. Собрать сервис, проверить восстановление после сбоев и запустить бумажную торговлю.
6. Параллельно писать текст ВКР и готовить материалы для защиты.

Отладка начинается на одной паре, основные сравнения — на нескольких. Начальный режим — спот без плеча. Свечи, горизонты и окна подбираются, а не фиксируются заранее. Реальные сделки и ассистент остаются расширениями после готовности ядра.

Подробная последовательность — в [плане](docs/plan.md), правила сравнения — в [протоколе экспериментов](docs/experiment_protocol.md). Сроки уточняются после проверки источников и требований кафедры.

## Структура

Код пайплайна — в `src/`, настройки — в `configs/`, тесты — в `tests/`, исследовательские ноутбуки — в `notebooks/`. Команды запуска — в `scripts/`. Записи запусков — в `experiments/`. Большие данные и модели хранятся отдельно; ключи и секреты в Git не попадают.

Загрузка и сборка (Python 3.9+, без сторонних библиотек):

```bash
python3 scripts/market_data.py download --config configs/btcusdt_1h_4h.json
python3 scripts/market_data.py build --config configs/btcusdt_1h_4h.json
python3 scripts/market_data.py verify-build --config configs/btcusdt_1h_4h.json
python3 -m unittest discover -s tests -v
```

Команды выполняются из корня проекта. При наличии завершённого снимка повторная загрузка не обращается к сети. Полная инструкция, короткий пилот и правила хранения — в [описании пайплайна](docs/data_pipeline.md). Это сборка исследовательских данных; торговая система ещё не реализована.
