# Тесты

Все проверки запускаются без сети в зафиксированном окружении:

```bash
uv run --locked python -m unittest discover -s tests -v
```

В `test_source_probe.py` проверяются повторы вместе с пропущенной граничной точкой, полуоткрытые диапазоны, некорректные/неоконченные свечи, отсутствующая метрика при наличии строки, UTC и наносекундные метки Coin Metrics, отсчёт задержки от конца дня, сохранение свидетельств при таймауте/неполном HTTP-теле и повторное использование ответов с защитой от изменения файла.

`test_download.py` проверяет контрольные точки, остановку между записью raw и SQLite, отсутствие дублей, конфликты, границы пропусков, повторное использование снимка, таймауты, повреждённый gzip и ограничения 429/418. `test_build.py` проверяет формулы фичей и ответа, точные минуты, повреждённые окна, отсечение будущих часовых входов, границы частей, неизменность хешей и атомарность пересборки.

`test_metrics.py` проверяет ручные RMSE/MAE, границы кварталов UTC и отказ при некорректных массивах. `test_train.py` проверяет список фичей, обучение только на разрешённом периоде, базовый прогноз по обучающей средней, фиксированные настройки, запись неудачных попыток, общий бюджет и восстановление артефактов. Для модельных тестов используется подмена CatBoost: исследовательский бюджет они не расходуют. Реальные сохранённые модели отдельно проверяет команда `verify` без вызова обучения.

`test_diagnostics.py` проверяет ручное разложение MSE, парные превышения ошибок, UTC-срезы, взвешивание, обучающие пороги, пустые группы, одинаковые значения и нулевые знаменатели. `test_diagnose.py` проверяет закреплённые хеши, совпадение строк, запрет обучения, сохранность входов и повторяемость сводки. Графики дополнительно проверяются визуально на реальной диагностике.

`test_attempts.py` проверяет смешанный старый/новый журнал, разные варианты одной глубины, неудачи, прерывания и учёт без общего предела. `test_control_metrics.py` проверяет парные формулы и квартальные веса. `test_controls.py` проверяет новую границу 2022/2023, фичи 18/11, базовую среднюю только по внутреннему обучению, ровно три фиксированных вызова, запрет обучения при `verify`, сохранение ошибок и неизменность данных. Подменённый backend не расходует реальные обучения.

По мере реализации пайплайна добавляются проверки:

- Регулярного обновления источников и исторической доступности дополнительных признаков.
- Бэктеста: покупки, продажи, расходы, размер заявки и недостаток средств.
- Стратегии: риск-лимиты и одновременные сигналы при общем капитале.
- Сервиса: повторная обработка, недоступность источника, остановка между решением и записью сделки.

Отдельная проверка сопоставляет решения бэктеста и сервиса на одинаковых входах, модели и состоянии счёта.

Торговый пайплайн пока не реализован; перечисленные проверки бэктеста и сервиса ещё не выполнены.
